## Описание реализации

### Товар

Класс `Product` представляет отдельный товар интернет-магазина. Он содержит закрытые поля для хранения идентификатора, названия и цены.

Для получения данных предусмотрены публичные методы `GetId()`, `GetTitle()` и `GetPrice()`. Метод `SetPrice(int)` позволяет изменять цену с проверкой допустимого значения. Метод `GetInfo()` формирует текстовое описание товара.

Проверка входных данных выполняется внутри класса, что предотвращает создание товаров с некорректными параметрами.

**Файл решения:** `Domain/Product.cs`.

### Каталог товаров

Класс `Catalog` отвечает за управление коллекцией товаров. Внутренний список товаров объявлен как закрытое поле.

Реализованы следующие методы:

- `Add(Product)` - добавляет товар с проверкой на `null` и наличие дубликатов.
- `Remove(string)` - удаляет товар по названию.
- `Find(string)` - выполняет поиск товара по названию.
- `GetProducts()` - возвращает копию списка товаров, доступную только для чтения через интерфейс `IReadOnlyList<Product>`.
- `GetCount()` - возвращает количество товаров в каталоге.

Для сравнения названий используется нормализация строк, позволяющая находить совпадения без учёта регистра и лишних пробелов.

**Файл решения:** `Domain/Catalog.cs`.

### Интерфейс хранилища и работа с JSON

Интерфейс `IProductRepository` определяет контракт для сохранения и загрузки товаров:

- `Save(IEnumerable<Product>)` - сохраняет переданный список товаров.
- `Load()` - загружает список товаров из хранилища.

Класс `FileProductRepository` реализует данный интерфейс и отвечает за взаимодействие с файловой системой.

Для сериализации и десериализации используется библиотека `System.Text.Json`. Данные сохраняются в файл `products.json`. При отсутствии файла метод загрузки возвращает пустой список.

Для преобразования объектов `Product` в формат JSON используется вспомогательный класс `ProductData`.

**Файлы решения:** `DataAccess/IProductRepository.cs`, `DataAccess/FileProductRepository.cs`.

### Вывод каталога

Класс `CatalogPrinter` отвечает за отображение информации о товарах.

Реализованы два основных метода:

- `PrintAll(IEnumerable<Product>)` - выводит полный список товаров.
- `PrintTop(IEnumerable<Product>, int)` - выводит заданное количество наиболее дорогих товаров в порядке убывания цены.

Для подготовки строки с информацией о товаре используется закрытый метод `PrepareLine(Product)`.

Дополнительно реализован файловый класс `PriceFormatter`, который форматирует цену товара для вывода.

**Файл решения:** `Presentation/CatalogPrinter.cs`.

### Отчёт по каталогу

Класс `CatalogReport` предназначен для анализа содержимого каталога.

Реализованы методы:

- `GetAveragePrice(IEnumerable<Product>)` - рассчитывает среднюю цену товаров.
- `GetSummary(IEnumerable<Product>)` - формирует текстовую сводку с количеством товаров, средней, минимальной и максимальной ценой.

При отсутствии товаров метод формирования сводки возвращает сообщение о пустом каталоге.

**Файл решения:** `Presentation/CatalogReport.cs`.

### Точка входа и демонстрация работы

В `Program.cs` собраны сценарии демонстрации функциональности проекта.

Программа последовательно показывает:

## Применение принципов ООП и SOLID

### Инкапсуляция

В классе `Product` поля идентификатора, названия и цены являются закрытыми. Изменение и получение данных выполняется через публичные методы.

В классе `Catalog` внутренняя коллекция также скрыта от внешнего доступа. Метод `GetProducts()` возвращает копию списка, поэтому внешнее изменение полученной коллекции не влияет на исходный каталог.

### Модификаторы доступа

В проекте используются следующие модификаторы:

- `public` - для классов и методов, доступных другим компонентам приложения;
- `private` - для внутренних полей и вспомогательных методов;
- `readonly` - для полей, значение которых должно оставаться неизменным после инициализации.

Также используется модификатор `file` для ограничения области видимости вспомогательного класса `PriceFormatter пределами одного файла.

### Принципы SOLID

- **SRP (Single Responsibility Principle)** - каждый класс отвечает за отдельную задачу. Например, `Catalog` управляет товарами, `FileProductRepository` работает с файлами, `CatalogPrinter` отвечает за вывод, а `CatalogReport` выполняет анализ данных.
- **OCP (Open/Closed Principle)** - использование интерфейса `IProductRepository` позволяет добавлять новые реализации хранилища без необходимости изменять код, который работает с интерфейсом.
- **LSP (Liskov Substitution Principle)** - любая корректная реализация `IProductRepository` должна заменять другую реализацию без нарушения ожидаемого поведения программы.
- **ISP (Interface Segregation Principle)** - интерфейс `IProductRepository` содержит только необходимые операции сохранения и загрузки товаров.
- **DIP (Dependency Inversion Principle)** - взаимодействие с хранилищем организовано через абстракцию `IProductRepository`, а не через привязку к конкретной реализации файлового хранилища.
